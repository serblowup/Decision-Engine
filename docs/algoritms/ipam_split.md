# Алгоритм SPLIT (разбиение подсети)

## Назначение

Алгоритм SPLIT применяется, когда один VLAN становится слишком большим и его необходимо разделить на два независимых сегмента. При этом IP-подсеть исходного VLAN разбивается на две дочерние подсети с увеличенной маской.

## Условия применения

- Количество устройств в VLAN превышает заданный порог
- IP-префикс VLAN позволяет выполнить разбиение (маска не более /30)

## Входные данные

- `vlan_id` — идентификатор VLAN, который требуется разбить
- `new_vlan_ids` — кортеж из двух новых VLAN ID для дочерних сегментов
- `ip_prefix` — текущий IP-префикс VLAN (получается из PostgreSQL)

## Выходные данные

- `SplitResult` — объект, содержащий:
  - `parent_vlan_id` — идентификатор исходного VLAN
  - `child1_vlan_id`, `child2_vlan_id` — идентификаторы дочерних VLAN
  - `child1_prefix`, `child2_prefix` — IP-префиксы дочерних подсетей
  - `child1_gateway`, `child2_gateway` — адреса шлюзов дочерних подсетей

## Пошаговое описание алгоритма

### Шаг 1. Получение текущего IP-префикса

Модуль обращается к базе данных PostgreSQL и получает текущий IP-префикс VLAN. Например, для VLAN 10 это может быть префикс `192.168.10.0/24`.

Если префикс отсутствует, операция прерывается с исключением `VLAN has no IP prefix`.

### Шаг 2. Проверка возможности разбиения

Проверяется длина маски префикса. Если длина маски больше или равна 30, разбиение невозможно, так как дочерние подсети будут слишком малы. Операция прерывается с исключением `Prefix too small for split`.

### Шаг 3. Вычисление дочерних префиксов

С помощью метода `SubnetCalculator.split()` вычисляются два дочерних префикса. Маска увеличивается на единицу, а исходная подсеть делится на две равные части.

Например, из префикса `192.168.10.0/24` получаются:
- `192.168.10.0/25`
- `192.168.10.128/25`

### Шаг 4. Назначение адресов шлюзов

Для каждого дочернего префикса вычисляется адрес шлюза как первый адрес подсети. Метод `SubnetCalculator.get_gateway()` возвращает:
- для `192.168.10.0/25` — `192.168.10.1`
- для `192.168.10.128/25` — `192.168.10.129`

### Шаг 5. Проверка конфликтов

Выполняется проверка, не пересекаются ли дочерние префиксы с существующими VLAN в базе данных. Для этого вызывается метод `_check_conflicts()` для каждого дочернего префикса. Исходный VLAN исключается из проверки, так как он будет удалён.

Если обнаружен конфликт, операция прерывается с исключением `Prefix overlaps with existing VLAN`.

### Шаг 6. Генерация действий

Формируются действия для Config Manager:

1. `DELETE_SUBINTERFACE` — удаление старого SVI на маршрутизаторе
2. `CREATE_SUBINTERFACE` — создание первого нового SVI
3. `CREATE_SUBINTERFACE` — создание второго нового SVI
4. `UPDATE_VLAN_PREFIX` — обновление записей о префиксах в базе данных

### Шаг 7. Сохранение в базу данных

Новые VLAN с присвоенными префиксами и адресами шлюзов сохраняются в PostgreSQL. Исходный VLAN помечается как удалённый.

## Генерируемые действия

```json
[
  {"action_type": "DELETE_SUBINTERFACE", "params": {"vlan_id": 10}},
  {"action_type": "CREATE_SUBINTERFACE", "params": {"vlan_id": 20, "ip_address": "192.168.10.1/25"}},
  {"action_type": "CREATE_SUBINTERFACE", "params": {"vlan_id": 30, "ip_address": "192.168.10.129/25"}},
  {"action_type": "UPDATE_VLAN_PREFIX", "params": {...}}
]
```

## Обработка ошибок

| Ситуация | Исключение |
|----------|------------|
| VLAN не имеет IP-префикса | `VLAN has no IP prefix` |
| Маска префикса ≥ 30 | `Prefix too small for split` |
| Дочерний префикс пересекается с существующим VLAN | `Prefix overlaps with existing VLAN` |
