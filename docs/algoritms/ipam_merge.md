# Алгоритм MERGE (слияние подсетей)

## Назначение

Алгоритм MERGE применяется, когда два VLAN имеют небольшое количество устройств и между ними наблюдается значительный межсегментный трафик. Объединение VLAN позволяет снизить нагрузку на маршрутизатор и упростить управление сетью. При этом IP-подсети двух VLAN объединяются в одну общую подсеть.

## Условия применения

- Два VLAN имеют небольшое количество устройств
- Между VLAN наблюдается высокий межсегментный трафик
- IP-префиксы VLAN являются смежными и могут быть объединены

## Входные данные

- `vlan_id_1` — идентификатор первого VLAN
- `vlan_id_2` — идентификатор второго VLAN
- `target_vlan_id` — идентификатор VLAN, который останется после слияния
- `prefix1`, `prefix2` — IP-префиксы двух VLAN (получаются из PostgreSQL)

## Выходные данные

- `MergeResult` — объект, содержащий:
  - `vlan1_id`, `vlan2_id` — идентификаторы исходных VLAN
  - `merged_vlan_id` — идентификатор объединённого VLAN
  - `merged_prefix` — IP-префикс объединённой подсети
  - `merged_gateway` — адрес шлюза объединённой подсети

## Пошаговое описание алгоритма

### Шаг 1. Получение IP-префиксов

Модуль обращается к базе данных PostgreSQL и получает IP-префиксы двух VLAN, которые требуется объединить.

Например:
- VLAN 10: `192.168.10.0/25`
- VLAN 20: `192.168.10.128/25`

Если хотя бы один из префиксов отсутствует, операция прерывается с исключением `VLAN has no IP prefix`.

### Шаг 2. Нахождение минимального надпрефикса

С помощью метода `SubnetCalculator.merge()` вычисляется минимальный надпрефикс, который покрывает обе подсети. Для этого маска уменьшается на единицу до тех пор, пока оба префикса не окажутся в пределах одной подсети.

Например, из префиксов `192.168.10.0/25` и `192.168.10.128/25` получается:
- `192.168.10.0/24`

При этом проверяется, что префиксы являются смежными и полностью покрывают надпрефикс. Если это не так, операция прерывается с исключением `Subnets are not in the same supernet`.

### Шаг 3. Вычисление адреса шлюза

Для объединённой подсети вычисляется адрес шлюза как первый адрес подсети. Метод `SubnetCalculator.get_gateway()` возвращает:
- для `192.168.10.0/24` — `192.168.10.1`

### Шаг 4. Проверка конфликтов

Выполняется проверка, не пересекается ли объединённый префикс с существующими VLAN в базе данных. Для этого вызывается метод `_check_conflicts()`. Исходные VLAN исключаются из проверки, так как они будут удалены.

Если обнаружен конфликт, операция прерывается с исключением `Prefix overlaps with existing VLAN`.

### Шаг 5. Генерация действий

Формируются действия для Config Manager:

1. `DELETE_SUBINTERFACE` — удаление первого старого SVI
2. `DELETE_SUBINTERFACE` — удаление второго старого SVI
3. `CREATE_SUBINTERFACE` — создание нового SVI для объединённого VLAN
4. `UPDATE_VLAN_PREFIX` — обновление записи о префиксе в базе данных

### Шаг 6. Сохранение в базу данных

Объединённый VLAN с новым префиксом и адресом шлюза сохраняется в PostgreSQL. Второй VLAN помечается как удалённый.

## Генерируемые действия

```json
[
  {"action_type": "DELETE_SUBINTERFACE", "params": {"vlan_id": 10}},
  {"action_type": "DELETE_SUBINTERFACE", "params": {"vlan_id": 20}},
  {"action_type": "CREATE_SUBINTERFACE", "params": {"vlan_id": 10, "ip_address": "192.168.10.1/24"}},
  {"action_type": "UPDATE_VLAN_PREFIX", "params": {...}}
]
```

## Обработка ошибок

| Ситуация | Исключение |
|----------|------------|
| VLAN не имеет IP-префикса | `VLAN has no IP prefix` |
| Префиксы имеют разную длину маски | `Prefix lengths differ` |
| Префиксы не являются смежными | `Subnets are not in the same supernet` |
| Объединённый префикс пересекается с существующим VLAN | `Prefix overlaps with existing VLAN` |
